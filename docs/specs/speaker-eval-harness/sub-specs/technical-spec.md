# Technical Specification

This is the technical specification for the spec detailed in docs/specs/speaker-eval-harness/spec.md

> Created: 2026-10-29
> Version: 1.0.0

## Technical Requirements

### Session folder layout

```
eval/                          # audio git-ignored; only labels.json and session.json are committable
  2026-11-02-pub/
    session.json               # metadata: venue, notes, members, sync offsets
    table.wav                  # what the app would record (shared phone)
    enroll/<member>.wav        # ~10 s enrollment sample per member, as the app would take it
    tracks/<member>.wav        # dev-only: member's own device recording (for label generation)
    labels.json                # ground truth (generated by `label`, hand-editable)
```

`session.json`:

```json
{
  "venue": "pub",
  "members": ["Maria", "Dev", "Sam", "Lee"],
  "trackOffsetsSeconds": { "Maria": 0.0, "Dev": 0.42 }
}
```

`trackOffsetsSeconds` aligns each personal track to `table.wav` (the offset to add to a track timestamp). Sync method: everyone claps once at the start; `label` finds the clap peak in each track and in `table.wav` and proposes offsets, which `session.json` can override.

`labels.json`:

```json
{
  "intervals": [
    { "speaker": "Maria", "start": 12.40, "end": 17.85 },
    { "speaker": "Dev",   "start": 17.20, "end": 19.10 }
  ],
  "nonMemberSpans": [ { "start": 300.0, "end": 330.0 } ]
}
```

Intervals may overlap (crosstalk). `nonMemberSpans` marks stretches of clearly non-member speech so they aren't scored as errors later.

### Commands

| Command | Behavior |
|---|---|
| `minits-eval label <session>` | Reads `tracks/*.wav` + offsets, computes speech activity per track (energy gate with the same shape as `trimSilence`, 20 ms frames, hangover 300 ms), resolves bleed by assigning a frame to the track with the highest energy when several are active unless both exceed `0.5 * peak` (then both, marking overlap), writes `labels.json`. |
| `minits-eval run <dir-or-session> [flags]` | For each session: enroll each member via `VoiceEngine.voiceprint(forSampleAt:)`, call `process(meetingAt: table.wav, voices:)`, score, print. |
| `minits-eval compare <a.json> <b.json>` | Prints metric deltas between two reports. |
| `minits-eval check <session>` | Before labeling: lists each track's length, clap offset and enrollment length, and reports problems (missing or misnamed files, non-WAV audio, enrollment outside the app's 4-15 s) and warnings (table under 15 min, a track shorter than the table, no clap). Exits non-zero on problems. |
| `minits-eval spotcheck <session> [--count 20]` | After labeling: cuts `count` labeled intervals (≥ 1 s, evenly spread, deterministic) from `table.wav` into `spotcheck/` with a `checklist.md` to fill in by ear. Bar: 19 of 20 correct. |

Flags for `run`: `--accept-similarity`, `--sure-similarity`, `--minimum-margin`, `--override-gap`, `--out report.json`.

### Tuning injection (the only change to app code)

```swift
struct VoiceTuning: Sendable {
    var acceptSimilarity: Float = 0.40
    var sureSimilarity: Float = 0.50
    var minimumMargin: Float = 0.06
    var overrideGap: Float = 0.10      // the literal in process()
}
actor VoiceEngine { init(tuning: VoiceTuning = .init()) ... }
```

`static let shared` keeps using defaults. The magic `0.10` in `process` becomes `tuning.overrideGap`. No behavior change with defaults.

### Scoring

The scorer lives in `Minits/Eval/` and has no FluidAudio dependency. It takes `LineUnderTest` values (member name or nil for guest, `needsReview`, `confidence`, times); the CLI maps `ProcessedLine` into them. `Minits/Eval/` is excluded from the app target and compiled into the `MinitsEvalTests` and (later) `minits-eval` targets.

Each output `ProcessedLine` is matched to ground truth by time:

- Ground-truth speaker of a line = the labeled speaker with the greatest overlap in `[start, end]`. If two labeled speakers each cover over 30% of the line, the line is **overlap**.
- Lines whose dominant span is inside `nonMemberSpans`, or that have no labeled speaker, are **non-member** lines.
- A line is **correct** if `speakerID`'s member equals the ground-truth speaker. Guest lines are correct only for non-member lines.

Metrics (per session and pooled over all sessions by line count, and also weighted by line duration):

| Metric | Definition |
|---|---|
| Attribution accuracy | correct / scored lines |
| Unflagged error rate | wrong AND `needsReview == false` / all scored lines. **Primary metric; target under 1%.** |
| Flagged rate | `needsReview == true` / all lines |
| Flag recall | wrong lines that are flagged / wrong lines |
| Review burden | estimated review minutes per hour of meeting = flagged lines' total audio seconds * 1.0 (play once at real time) + 4 s per flagged line (decide and tap), scaled to 60 min. **Target at most 10.** |
| Overlap and short-line breakdown | the same metrics restricted to overlap lines and to lines under 1 s |
| Confusion matrix | true speaker by attributed speaker, for spotting a similar-voice pair |

Both rates are also reported per confidence bucket (`confidence` 0-0.25, ...) to show whether `confidence` is calibrated.

### Report

Table to stdout and JSON to `--out`, including the tuning used, FluidAudio version, session list, all metrics above, and the list of wrong-and-unflagged lines (`session`, `start`, `text`, `true`, `got`, `score`) so each one can be listened to.

## Approach Options

**Option A: XCTest target.** Pros: fits Xcode flow. Cons: awkward arguments, slow iteration, poor for large local audio.

**Option B: macOS command-line tool target (Selected).** Pros: flags for threshold sweeps, scriptable, JSON output diffable in git. Cons: one more target in `project.yml`.

**Option C: Separate Swift package.** Pros: clean separation. Cons: needs `VoiceEngine` shared via a package, forcing a larger refactor than this spec warrants.

**Rationale:** B keeps the engine file single-sourced (the CLI target lists `Minits/Voice/VoiceEngine.swift` as a source) with the smallest app change.

## External Dependencies

- **swift-argument-parser** - subcommands and flags. **Justification:** Apple-maintained, standard for Swift CLIs; the alternative is hand-parsing three subcommands with several flags.
- No others. FluidAudio is already a dependency.

## Notes and Risks

- `VoiceEngine.swift` imports only FluidAudio and Foundation, so it compiles in a macOS CLI target on its own; confirm `EnrolledVoice` / `ProcessedLine` stay in that file.
- Pub ground truth depends on clean personal tracks. Bleed from the table into personal devices is the main labeling risk; keep devices near each mouth and spot-check 20 labeled intervals by ear per session.
- FluidAudio model download happens on first run; the CLI needs network once, then works offline.
- Real pub audio contains identifiable people. Keep `eval/**/*.wav` out of git by adding it to `.gitignore`.
